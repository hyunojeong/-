# VDI 반입 가이드

이 문서는 `idea-platform/`을 폐쇄망 VDI 안으로 가져가기 위해 확인해야 할 사항을
정리한 것입니다. 회사마다 반입 심사 절차·기준이 다르므로, 아래는 "무엇을 확인시켜주면
심사가 수월할지"에 대한 체크리스트이지 승인을 보장하는 문서는 아닙니다. 실제 신청은
사내 보안팀 절차를 따라야 합니다.

## 1. 이 도구가 반입 심사에서 상대적으로 수월할 것으로 보는 이유

- **런타임에 외부 네트워크 호출이 전혀 없습니다.** `index.html`, `app.js`, `knowledge.js`
  어디에도 외부 도메인으로의 `fetch`, CDN 스크립트 태그, 트래킹 스크립트가 없습니다.
  아래 명령으로 직접 확인할 수 있습니다.

  ```bash
  grep -rn "http://\|https://" idea-platform/*.js idea-platform/*.html
  ```

  (결과는 `data/cases.json`·`knowledge/docs/*.md` 안의 **출처 링크 텍스트**뿐이어야
  합니다 — 이건 사용자가 클릭했을 때만 열리는 참고 링크지, 코드가 자동으로 호출하는
  주소가 아닙니다.)

- **빌드 도구/패키지 매니저가 필요 없습니다.** `package.json`, `node_modules`가 없고,
  `python3 -m http.server` 같은 표준 라이브러리 서버만 있으면 동작합니다. 즉 반입 후
  별도 인터넷 연결 없이 그대로 실행 가능합니다.

- **`knowledge/build_index.py`도 Python 표준 라이브러리(`json`, `re`, `pathlib`)만
  사용**하며 pip install이 필요 없습니다.

## 2. 반입 전 확인할 것

- [ ] `idea-platform/knowledge/docs/`의 샘플 문서 8건은 전부 "[샘플]" 표기가 있고
      일반 교과서 수준 설명만 담고 있어 기밀이 아님을 확인 (필요시 반입 전 삭제해도 무방 —
      데모용일 뿐 실행에는 필요 없음).
- [ ] `idea-platform/data/cases.json`의 38개 벤치마킹 사례는 전부 공개 논문/특허/업계지
      출처이며 `source.url`로 원문이 명시되어 있음을 확인.
- [ ] 위 grep 명령으로 외부 호출 코드가 없음을 재확인.
- [ ] 폴더 전체를 zip으로 압축 (예: `zip -r idea-platform.zip idea-platform/`).

## 3. 반입 절차 (일반적인 흐름 — 사내 절차에 맞게 조정 필요)

1. 자료반입 신청 시스템에 `idea-platform.zip`과 함께, 위 grep 결과 및 이 가이드를
   근거자료로 첨부.
2. 코드 리뷰가 필요하면 이 저장소 소스 전체(`idea-platform/` 폴더)를 그대로 제공 —
   전부 텍스트 기반 정적 파일이라 리뷰가 어렵지 않을 것으로 예상.
3. 승인 후 VDI 내 저장소로 복사.
4. VDI 안에서 `python3 -m http.server`로 구동 확인 (Python 3가 VDI에 이미 있는지
   사전 확인 필요 — 없다면 별도로 반입 신청 대상에 포함해야 함).

## 4. VDI 반입 후 해야 할 일 (사내 지식 결합)

**여기서부터는 기밀자료를 다루므로 반드시 VDI 내부에서만 진행하세요.**

1. 공정 매뉴얼·Knowledge book 원본(PDF/Word 등)을 사내 승인된 도구로 텍스트 변환.
2. `knowledge/docs/`의 샘플 파일을 실제 문서로 교체 (형식은
   `knowledge/README.md` 참고).
3. `cd knowledge && python3 build_index.py` 실행해 `index.json` 재생성.
4. `index.json`과 `docs/` 폴더는 이제 기밀자료를 포함하므로, 이 프로젝트를 다시
   외부로 반출하지 않도록 주의 (반대 방향 반출 심사도 필요).

## 5. 향후 확장 옵션 (지금 당장 필요한 건 아님)

- 사내에 승인된 온프레미스 LLM 게이트웨이가 생기면, 자연어 질의("우리 PP 공장 압축기
  관련 아이디어 줘")를 지금의 태그/키워드 검색으로 변환해주는 얇은 레이어만 추가하면 됩니다.
  현재 구조(정적 파일 + JSON 데이터 + 클라이언트 검색)를 갈아엎을 필요는 없습니다.
- 문서량이 늘어나 한국어 검색 정밀도가 아쉬워지면 `knowledge/build_index.py`의
  `tokenize()`를 사내 반입 가능한 한국어 형태소 분석기로 교체하는 것을 검토하세요.
