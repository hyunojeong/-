# 공정 최적화 아이디어 벤치마킹 엔진 (PoC)

딥한 공정 지식 없이도 "다른 곳에서는 이런 utility 절감/반제품 고부가화를 했다"는 사례를 우리 공장(Aromatic/Olefin/Polymer) 구조에 맞춰 추천해주는 프로토타입입니다. 여기에 더해, VDI 반입 후 실제 사내 공정 매뉴얼/Knowledge book을 검색할 수 있는 **사내 지식 검색 탭**을 결합했습니다 (`knowledge/` 참고, 지금은 데모용 샘플 문서만 들어있음).

## 왜 이렇게 만들었나

- **런타임에 외부 LLM 호출이 없습니다.** 순수 정적 파일(HTML/CSS/JS)과 로컬 JSON 데이터만으로 동작하는 태그 매칭 엔진입니다.
- 이유: 회사 VDI가 폐쇄망이라 외부 LLM API를 실시간으로 부를 수 없습니다. 이 구조라면 빌드도, 인터넷 접속도, 별도 서버 런타임도 필요 없이 **파일째로 복사해서 브라우저로 열기만 하면** VDI 안에서도 그대로 동작합니다. 보안팀 반입 심사도 "정적 웹페이지 + 텍스트 데이터"라서 상대적으로 수월할 것으로 예상됩니다.

## 실행 방법

```bash
cd idea-platform
python3 -m http.server 8000
# 브라우저에서 http://localhost:8000 접속
```

(fetch()로 로컬 JSON을 읽기 때문에 `index.html`을 `file://`로 직접 열면 브라우저 보안 정책상 막힐 수 있습니다. 반드시 간단한 정적 서버로 띄워서 열어주세요. `python3 -m http.server`는 파이썬만 있으면 인터넷 연결 없이 동작합니다.)

## 데이터 구조

- `data/taxonomy.json` — 사업부(Aromatic/Olefin/Polymer/Cross-Plant)와 공장(BTX, PX, Cracker, Butadiene, LLDPE, HDPE, PP, Nexlene), 카테고리(열통합, 압축기 효율, 폐열회수, Flare 저감, 반제품 고부가화, 공정/촉매 기술, APC) 정의.
- `data/cases.json` — 벤치마킹 사례 38건. 전부 공개 논문/특허/업계지 기사에서 조사했고, 각 항목에 `source.url`로 원문 링크를 달아뒀습니다. **회사 기밀자료는 전혀 포함되지 않았습니다** — 이 데이터는 외부에서 만들어 그대로 반입해도 되는 부분입니다.

각 사례는 `plants`(적용 가능 공장), `categories`(유형), `quantifiedBenefit`(정량 효과), `ideaPrompt`(우리 공장 맥락에 맞춘 적용 제안 문구)를 가지고 있습니다.

## 매칭 로직 (`app.js`)

- 사용자가 공장을 선택하면: 그 공장 태그와 겹치는 사례 + `utility`(전 공장 공통) 태그 사례를 점수순으로 보여줍니다.
- 카테고리 칩을 추가로 선택하면 가중치가 더해져 우선순위가 올라갑니다.
- 키워드 검색은 제목/요약/적용 아이디어 텍스트에 대한 단순 문자열 매칭입니다.
- LLM도, 서버도, 데이터베이스도 없습니다 — 전부 클라이언트 사이드 JS 필터링입니다.

## 사내 지식 검색 (`knowledge/`)

"사내 지식 검색" 탭은 `knowledge/index.json`(BM25 검색 인덱스)을 로드해 동작합니다.
- 인덱스는 `knowledge/build_index.py`(Python 표준 라이브러리만 사용, pip install 불필요)로 `knowledge/docs/*.md`에서 생성합니다.
- 지금 `docs/`에는 **데모용 샘플 문서 8건**만 있습니다. 실제 사내 자료로 교체하는 방법은 `knowledge/README.md`를 참고하세요.
- 벤치마킹 사례 탭과 공장 필터를 공유하므로, 예를 들어 "Cracker"를 선택하면 관련 벤치마킹 사례와 관련 사내 자료가 동시에 좁혀집니다.

## VDI 반입

`VDI_반입_가이드.md`에 반입 전 체크리스트와 절차, 반입 후 사내 지식 결합 단계를 정리해뒀습니다. 핵심은: 이 코드는 런타임에 외부 네트워크를 전혀 호출하지 않고(`grep`으로 직접 검증 가능), 빌드 도구도 필요 없는 순수 정적 파일이라는 점입니다.

## 다음 단계 (제안)

1. **사례 확충**: 벤치마킹 사례 38건도 여전히 시작점입니다. `data/cases.json`에 추가하면 바로 반영됩니다 (엔진 코드 수정 불필요). Nexlene(용액중합)처럼 상대적으로 사례가 적은 공장은 우선 보강 대상입니다.
2. **VDI 반입 & 사내 지식 결합 (실행)**: `VDI_반입_가이드.md` 절차대로 반입 신청 → 승인 후 VDI 내부에서 `knowledge/docs/`를 실제 매뉴얼로 교체 → `build_index.py` 재실행. 이 단계는 실제 사내 승인/네트워크 접근이 필요해 이 세션에서는 코드/가이드 준비까지만 진행했습니다.
3. **정량 매칭 고도화**: 지금은 태그/키워드 매칭이지만, 사용자 피드백("이 사례 유용했음/아니었음")을 쌓아 스코어링을 개선하거나, 사내 승인된 온프레미스 LLM 게이트웨이가 생기면 자연어 질의("우리 PP 공장 압축기 관련 아이디어 줘")를 태그/검색어로 변환하는 레이어만 얹으면 됨 — 지금 구조를 갈아엎지 않아도 확장 가능.
4. **한국어 검색 정밀도 개선**: 지금은 형태소 분석기 없이 문자 bigram으로 흉내낸 방식입니다. 문서량이 늘면 사내 반입 가능한 한국어 형태소 분석기로 교체를 검토하세요 (`knowledge/README.md`의 한계 섹션 참고).
