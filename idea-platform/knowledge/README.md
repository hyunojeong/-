# 사내 지식 검색 모듈

VDI 반입 후 실제 공정 매뉴얼/Knowledge book을 색인해 벤치마킹 사례와 함께 검색할 수 있게
하는 모듈입니다. 지금 `docs/` 안에는 **데모용 샘플 문서 8건**만 들어있습니다 — 전부
"[샘플]" 표시가 붙어 있고, 일반 공정공학 교과서 수준의 통념적 설명만 담고 있어 기밀
정보가 전혀 아닙니다. 파이프라인(문서 → 색인 → 검색)이 실제로 동작하는지 보여주기 위한
자리표시자(placeholder)입니다.

## 왜 임베딩(벡터) 검색이 아니라 BM25(키워드 검색)인가

폐쇄망 VDI 안에서 pip install 없이, 대용량 임베딩 모델 weight를 반입하지 않고도 바로
동작해야 한다는 제약 때문입니다. BM25는 Python 표준 라이브러리만으로 구현 가능하고,
검색 품질도 키워드 기반 문서 검색에는 충분히 실용적입니다. 온프레미스 임베딩 모델이
승인되면 `build_index.py`의 색인 로직만 교체하면 됩니다 (프론트엔드 인터페이스는 그대로
유지 가능).

## 사용 방법

1. `docs/` 폴더의 샘플 `.md` 파일들을 실제 자료로 교체합니다 (또는 새 파일을 추가합니다).
   형식은 다음과 같습니다:

   ```
   id: doc-001
   title: 문서 제목
   plants: btx, px
   ---
   본문 내용...
   ```

   PDF/Word 형태의 매뉴얼은 사내에서 사용 가능한 문서 변환 도구로 먼저 텍스트를 추출해야
   합니다 (이 저장소에는 PDF 파서를 포함하지 않았습니다 — 사내 승인된 도구를 쓰는 것이
   안전합니다).

2. 인덱스를 재생성합니다.

   ```bash
   cd knowledge
   python3 build_index.py
   ```

   `index.json`이 갱신됩니다. 이 파일이 실제 검색에 쓰이는 결과물이며, 원본 `docs/`
   텍스트도 `excerpt` 형태로 일부 포함되므로 **`index.json`도 `docs/`와 동일하게 기밀
   취급**해야 합니다.

3. `idea-platform/` 루트에서 정적 서버를 띄우면 "사내 지식 검색" 탭에서 바로 검색됩니다.
   공장 필터는 벤치마킹 사례 탭과 공유됩니다.

## 한계 (알고 시작하기)

- 한국어 형태소 분석기 없이 문자 bigram으로 흉내낸 방식이라, 정교한 형태소 분석 대비
  검색 정밀도가 떨어질 수 있습니다. 프로토타입 단계에서는 충분하지만, 문서량이 많아지고
  사용자가 늘면 사내 반입 가능한 한국어 형태소 분석기(mecab-ko 등)로 `tokenize()`를
  교체하는 것을 권장합니다.
- 문서 수가 매우 많아지면(수천 건 이상) 브라우저에서 `index.json`을 통째로 로드하는 방식이
  느려질 수 있습니다. 그 시점에는 검색을 서버 사이드(사내 승인된 경량 서버)로 옮기는 것을
  고려하세요.
